# Скачивание модулей Foundry VTT

Отдельный скрипт на Python 3.12+, без установки зависимостей. Запуск из корня репозитория:

```powershell
py -3.12 tools/foundry_downloader/download.py --list manifests.txt --output D:/Foundry-staging
```

Создайте `manifests.txt`: один URL манифеста на строку, пустые строки и строки с `#` пропускаются. Ссылки с токенами храните локально, не добавляйте в Git. Можно передать один или несколько URL напрямую:

```powershell
py -3.12 tools/foundry_downloader/download.py "https://example.com/module.json" --output D:/Foundry-staging
```

Скрипт делает GET манифеста, читает `id` (либо старое `name`) и `download`, скачивает ZIP во временный файл и распаковывает. Поддерживаются архивы с файлами в корне или с вложенной папкой модуля. Результат: `D:/Foundry-staging/<id>/module.json` и ресурсы рядом. Временные файлы удаляются после успеха или ошибки; существующие папки пропускаются без перезаписи. Для повторного скачивания используйте новую выходную папку.

После завершения вручную перенесите папки модулей в `Data/modules` вашего пользовательского каталога Foundry. Скрипт не меняет файлы Foundry, не активирует модули, не подбирает совместимые версии и не скачивает зависимости. Нужны прямые HTTP(S)-ссылки, доступные без браузерной авторизации; перенаправления поддерживаются. Загружается версия из указанного манифеста, а не версия, автоматически подобранная под Foundry.

Обработка последовательная; ошибка одного URL не мешает следующим. Код выхода 0 — всё скачано или пропущено, 1 — есть ошибки. `--timeout 120` задаёт таймаут сетевого ожидания, не лимит длительности всего скачивания. Для больших карт нужно место одновременно под ZIP и распакованные данные.

Формат: [манифест модуля](https://foundryvtt.com/article/module-development/), [ручная установка](https://foundryvtt.com/article/modules/).

Проверки без внешней сети:

```powershell
py -3.12 -m unittest discover -s tools/foundry_downloader -p "test_*.py" -v
```
