# Противоречия и неоднозначности

Сюда заносятся только реальные расхождения, обнаруженные при чтении книги или сравнении с прототипом.

Для каждой записи нужны:

- идентификатор;
- обе конфликтующие формулировки со ссылками на страницы;
- влияние на симуляцию;
- возможные трактовки без преждевременного выбора;
- решение пользователя и дата, когда оно появится.

## Обнаруженные расхождения

| ID | Книга | Прототип P1 | Решение |
|---|---|---|---|
| CONFLICT-001 | Пул ограничен удвоенной характеристикой | Глобальный максимум 10 кубов | Книга приоритетна; модель лимита нужно заменить |
| CONFLICT-002 | WS задаёт число кубов и для Melee, и для Defence; навык задаёт порог | WS и DEF представлены независимыми полными профилями | Перестроить модель на Characteristic + Skill |
| CONFLICT-003 | Защита выбирает Athletics или Defence по контексту и снаряжению | Любая атака защищается через DEF | Добавить выбор защитной проверки |
| CONFLICT-004 | Нулевые результаты означают провал обеих сторон; специального stagger защитнику нет | `0 против 0` накладывает stagger на обоих | Правило прототипа удалить при переходе на книгу |
| CONFLICT-005 | Штраф за промах действует только в Close Range | Любой промах атакующего создаёт stagger | Ограничить правилом дистанции |
| CONFLICT-006 | Повторный Staggered предлагает Give Ground, Prone или Wound | Второй stagger автоматически становится Wound | Реализовать выбор через контроллер/политику |
| CONFLICT-007 | Один ход обычно содержит одно действие, максимум два при особом источнике | Боец выполняет все настроенные атаки | K1 action slots реализованы по книге; P1 оставлен миграционным материалом |
| CONFLICT-008 | Игроки и GM выбирают порядок своей стороны каждый раунд; возможна засада | Порядок списка фиксирован, игроки всегда первые | K1 side/turn controller реализован; Awareness-определение засады ещё внешнее |
| CONFLICT-009 | Игроки и Champions используют таблицу Wounds; разные NPC имеют разные модели поражения | Все сущности имеют простой wound limit | Ввести стратегии/компоненты injury model по типу сущности |
| CONFLICT-010 | Resilience выводится из Toughness и снаряжения | RES хранится самостоятельным скаляром | Разрешать эффективный Resilience из компонентов |
| CONFLICT-011 | Area-эффекты задаются конкретным оружием, атакой или способностью; Monstrosity разрешает атаки отдельно | Прототип предполагает общий алгоритм AoE | Пользователь подтвердил, что правило было временным; удалить из целевой модели |
| CONFLICT-012 | Особый порог `1` применяется, только если модификаторы уменьшили пул ниже одного куба | P1 применяет порог `1` к любому пулу ровно из одного куба | Книги приоритетны; K1 реализует книжное правило, P1 оставлен без изменения только как миграционный материал |

Все перечисленные расхождения разрешены общей политикой источников в пользу книг. Фактический статус переноса каждого правила в K1 ведётся в `rule-traceability.md`; P1 остаётся только миграционным материалом.

## Неоднозначности внутри книг

| ID | Формулировки | Влияние | Временная политика |
|---|---|---|---|
| AMBIGUITY-001 | Player’s Guide, 119: невозможный Give Ground нельзя выбрать; GM Guide, 177, 179–180: Monstrous Flight при Reaction требует Give Ground и задаёт Wound только после уже выполненного Give Ground в текущем ходу | Не определён исход Reaction для Prone или полностью заблокированной Monstrosity | K1 явно останавливает эту ветвь; скрытая Wound или потеря Reaction не назначается до ruling пользователя/GM |
| AMBIGUITY-002 | Player’s Guide, 78 и GM Guide, 182: заклинание, затрагивающее устойчивую цель, «reduces its Potency by 1»; multi-target область действия не уточнена | Неясно, уменьшается ли Potency глобально для всех целей либо только effective Potency против устойчивой цели | K1 применяет modifier отдельно к защищённой цели; остальные цели сохраняют исходную Potency |
| AMBIGUITY-006 | Player’s Guide 1.4, страница 93: Greatsword содержит `+1 to Defence`, тогда как Sword/Glaive и терминология модификаторов используют `+1d to Defence` | Неясно, пропущена ли `d` в книге/текстовом слое и какой тип модификатора должен иметь профиль | Не реализовывать modifier Greatsword до визуальной проверки страницы либо официального уточнения; остальные weapon profiles не затронуты |
| AMBIGUITY-007 | Player’s Guide 1.4, страница 117: Charge даёт `+1d`, «if this is a Melee attack»; страница 118 вводит следующий список как modifiers для Melee и Brawn attacks и включает туда Charge | Неясно, получает ли unarmed Brawn Attack бонус Charge либо слово Melee на странице 117 обозначает только Skill | K1 временно следует более конкретному определению Charge и добавляет `+1d` только для `Skill.MELEE`; Brawn Charge исполняется без бонуса до ruling пользователя/GM |
| AMBIGUITY-008 | Player’s Guide 1.4, страница 121: end-battle Recover автоматически обрабатывает все Wounds при возможности перевести дух; там же каждую injury разрешено обрабатывать только с подходящими trappings | Не определён исход, когда инструменты подходят лишь для части ран | K1 требует explicit `has_required_trappings_for_all_wounds=True` и отклоняет partial batch без изменений; per-Wound policy остаётся внешней до inventory orchestration |
