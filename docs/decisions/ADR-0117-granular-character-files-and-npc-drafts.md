# ADR-0117: отдельные файлы персонажей и черновики составов

Дата: 2026-11-16. Статус: реализовано; пользователь выбрал замену NPC в черновике с сохранением исходного отчёта.

## Решение

Файл игрока — один объект `party_member` текущего Dynamic JSON1. Файл NPC — один элемент `candidate.npcs` того же контракта. Дополнительной оболочки, самостоятельной версии или compatibility-ветки нет: общие schema fragments остаются единственным определением допустимых данных. Экспорт сохраняет все исходные поля профиля, включая инвентарь, расходники, таланты и Fate игрока; UI-плейсхолдеры и статистика симуляций в файл не включаются.

В каждой карточке есть загрузка/скачивание. Загрузка игрока заменяет выбранного участника; рядом с добавлением игрока можно импортировать нового. ID должен быть уникален в партии; автоматического переименования нет. Результат помечается устаревшим по прежнему сравнению source request. Импорт и экспорт не запускают поиск.

## Граница проверки

`POST /api/character` принимает `{kind: "player" | "npc", document: "текст JSON файла"}` и возвращает проверенный профиль. Это stateless loopback endpoint с прежними Host/Origin, Content-Type, размером/timeout ограничениями, без generation lock и Run token. Текст файла читается строгим JSON parser: дубли ключей, float tokens и non-finite значения не теряются при предварительном клиентском `JSON.parse`. BOM допускается. Проверяются общие schema fragments, уникальность item IDs и талантов без учёта регистра.

Это проверка описания персонажа, без компиляции игрового loadout: можно сохранить уже разрешённый draft с ещё неисполняемыми предметами/талантами. Прежний preflight генератора продолжает отклонять неподдержанные игровые пути. NPC ограничен текущим composable source (WS/S/T/Ag, Melee/Athletics, Staff/Dagger, Light Armour и явно заданный Drained-on-hit); импорт не открывает новые Abilities.

## Черновик противников

Замена NPC изменяет отдельный browser draft выбранного состава, не `lastResult`, оценки, replay или JSON отчёта. Ключ — scenario ID кандидата и исходный список NPC; совпадающий исходный состав в нескольких представлениях получает один draft. Каждая изменённая карточка скачивается из draft.

В изменённом составе статистика подписана как исходная и неактуальная, рекомендация не распространяется на draft. Общее уведомление объясняет отличие карточек от JSON; скачивание полного результата сохраняет исходный отчёт. Скачать «бой черновика» нельзя: исходный replay отключается, чтобы не выдавать его за пересчитанный. Есть сброс отдельного состава; возвращение исходного NPC также снимает draft.

Прямой расчёт ручного draft в этой функции не добавлен. Кнопка генератора по-прежнему ищет новые составы по request, сбрасывая draft; загрузка другого полного результата также его сбрасывает. Изменение партии сохраняет открытый draft, но независимо помечает исходный отчёт устаревшим. Ошибочная загрузка полного результата не удаляет draft.

Версии операций и снимок целевой карточки защищают от запоздавших чтений/ответов, удаления или изменения цели и нового Run. Пока генератор занят, профильные действия заблокированы.

## Проверка

Адресные unit: полный roundtrip rich player draft, NPC без derived fields/report, строгий JSON, неверный вид/границы значений, дубли инвентаря/талантов. HTTP: stateless validation без запуска simulator, локальная граница и ошибки. Browser: иконки и обычные UI paths, обе загрузки/скачивания, добавление игрока, коллизии ID, сохранение полного инвентаря, stale source, NPC draft/сброс/replay block, исходный JSON неизменен, поздние файлы и блокировка при Run. Публичные примеры проверяются тем же parser. Full regression/wheel не нужны: игровой kernel, dependencies и discovery не менялись.
