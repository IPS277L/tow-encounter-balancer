# ADR-0004: round/turn state и action slots до полного battle loop

Статус: принято, 2026-08-20.

## Контекст

Player’s Guide 1.4 на страницах 111–112 и 116 задаёт два уровня порядка: стороны действуют последовательно, а внутри текущей стороны участники каждый раунд выбирают порядок заново и полностью завершают свой ход. Обычно доступен один action; Fate или Ability могут дать второй, но не третий. Один action нельзя повторить, второе действие не может дать вторую атаку, а два разных Improvise возможны только с разрешения GM. Charge на странице 117 классифицирован как Manoeuvre, но включает атаку.

Существующие K1 attack, casting и spatial reducers имеют разные входы и состояния. Их немедленное объединение в новый монолитный `BattleEngine` смешало бы проверку бюджета, расход ресурсов, выбор целей и исполнение эффектов до определения устойчивых границ.

## Решение

- Хранить неизменяемый `CombatRoundState`: номер раунда, снимок участников двух книжных сторон, persistent `side_order`, завершивших ход actor и не более одного активного хода.
- Выбирать actor внутри доступной стороны внешней policy; открывать следующую сторону только после завершения всех участников текущей.
- Передавать новый eligible participant snapshot при явном переходе к следующему раунду и сохранять side order, включая opposition-first после засады.
- Хранить в `CombatTurnState` actor и максимум два `CombatActionSlot`.
- Типизировать шесть действий, четыре варианта Manoeuvre и три источника Improvise: Skill, spell либо Ability. Считать Attack, Charge и явно помеченный атакующий Improvise формами, производящими атаку.
- Первый slot разрешать только как `STANDARD`; второй — только с provenance `FATE` либо `ABILITY` с конкретным Rule ID. Для `FATE` scheduler требует `FateSecondActionProof`, точно связанный с actor/round/slot request/declaration; raw grant отклоняется. Composite Fate consumer выполняет action-budget preflight, расходует session resource и резервирует slot одним результатом. Scheduler не читает `FateSessionState` и не мутирует состояние Ability.
- Запрещать одинаковые actions и вторую атаку как инварианты. Для двух Improvise требовать разные approach ID; дополнительно резолвер принимает явное разрешение GM.
- Считать slot разрешением на следующую фазу, а не исполненным действием. Attack/casting/movement reducers подключать отдельными узкими адаптерами с проверяемой связью входа и результата.
- После успешного специализированного executor добавлять к slot универсальную неизменяемую `ActionExecutionReceipt`; до этого slot остаётся только резервацией. Receipt сохраняет actor ID, round number, slot index и полную typed action declaration наряду с executor/source/result IDs. `CombatActionSlot`, `CombatTurnState` и `CombatRoundState` проверяют соответствующие части provenance, а execution IDs внутри одного turn уникальны.
- Для первого Attack adapter хранить actor, выбранный target ID, slot index, `KernelAttackRequest`, состояния хода до/после и вложенный `ResolutionResult`. Менять в round state только receipt выбранного slot; injury state не встраивать в scheduler.
- Для spell Improvise adapter хранить actor, slot index, `CastingTestRequest`, состояния хода до/после и вложенный `CastingTestResult`. Требовать совпадения stable approach ID с объявленным Lore и исполнять ровно один Casting Test, не применяя его follow-up и не принимая последующее решение `CAST`/`WAIT`.
- Для Skill Improvise хранить typed `SkillImproviseApproach`, один готовый basic/opposed Test и optional `SkillImproviseConditionEffect`. Stable approach ID обязан совпадать со slot; success и failure завершают действие. Наличие effect spec является явным GM approval и создаёт application request только при победе actor. Первую исполняемую схему ограничить книжными `Prone`/`Distracted`; другие creative outcomes не кодировать универсальным payload. Отдельная application boundary принимает завершённый action result, актуальные `ConditionState`/immunity snapshot цели и ordered snapshot уже потреблённых application IDs. Она проверяет полную action/Test/GM provenance, переиспользует общий Condition reducer, меняет только target Condition state и погашает source application ровно один раз. Атакующий Skill Improvise оставить отдельному kernel composite.
- Reload не добавлять как седьмой `CombatActionKind`: страница 116 ограничивает бой шестью actions, а страницы 94 и 117 позволяют представить Dexterity как специализированный Skill Improvise. Stable approach включает weapon instance; полный reload-подкаталог страницы 95 и factory привязывают его к конкретному weapon ID, free classification либо точной цели `2–5`. Числовой consumer привязывает общий Exacting progress к reload cycle, расходует один slot на одну Test и устанавливает loaded только при completion. Исходно loaded state не требует фиктивного cycle/progress. Узкий ranged composite допускает только Shooting из loaded state и исполняет обычный Attack: обычное reloadable оружие после hit/miss создаёт новый unloaded cycle, а Repeater делает это только при точном профильном optional bonus. Единый верхний adapter также исполняет free-профили без weapon transition; hidden и Aim потребляются отдельными композициями. Полный combat-каталог страницы 95 хранит range/Damage/hands и именованные traits отдельно от action-cost state, ссылаясь на reload profile по weapon ID. Чистая preparation boundary применяет эти поля к одному Attack, а optional Aim — после них через прежний follow-up, не исполняя kernel. Prepared executor принимает этот result как обязательный вход: без Aim делегирует unified path, с Aim — существующему Aim-bound consumer. Хранится один nested execution выбранного типа, полная preparation provenance и точная consumption chain; повторного kernel/receipt или применения modifiers нет. Ammunition остаётся отдельным контрактом.
- Ability Improvise подключать специализированными adapters конкретных Ability Rule ID, без универсального payload. Первый adapter Troll Vomit требует наличие `RULE-NPC-019:troll-vomit` в actor snapshot и точное совпадение approach ID, принимает одного идентифицированного вражеского Staggered target на Close Range с явным Endurance Test, затем атомарно исполняет общие Test/Hazard/Wound reducers. Target injury state остаётся вне round state, а receipt добавляется только после полного Hazard result. Vomit не считать Attack action: книга формулирует его как отдельное action и Hazard, без Attack Test.
- Второй Ability adapter Troll Hag Swamp Breath требует `RULE-NPC-020:swamp-breath`, отсутствие Defenceless/Staggered у actor, явный Medium Range fact и актуальный spatial snapshot. Target IDs обязаны в точности и в том же порядке совпасть со всеми placements выбранной Zone; не фильтровать союзников и включать actor, если он находится в ней. После preflight делегировать общему Zone Hazard batch на одном RNG и добавлять receipt только после всех целей. Spatial state не мутировать, обновлённые injury states оставить во вложенных target results будущему aggregate. Пустую Zone разрешать как выбранную Zone без существ и завершать action без RNG: книга требует Test только от находящихся там creatures и не задаёт обязательной цели-существа.
- Третий Ability adapter Forest Dragon Soporific Breath использует тот же closed Zone-action boundary, но отдельные Rule ID и Hazard (2) с failure Drained/repeated Defenceless. Проверять отсутствие Defenceless/Staggered, Medium Range и точный ordered placement snapshot до RNG; после Wound доказывать конкретную Condition application и только затем добавлять receipt. Wood Elf-наездник проходит тот же контракт при наличии Soporific Breath в подтверждённом actor Ability snapshot; не вводить общий rider engine. Как и для Swamp Breath, включать всех placements и разрешать пустую Zone.
- Подключать post-Test фазу отдельным контрактом: проверить provenance Rule of Nine, применить Miscast Pool threshold и только в normal-ветви принять готовый `CastingDecisionRequest` того же actor, Wizard Level и post-pool state. Triggered-ветвь не маскировать под `WAIT`: она сохраняет базовый Miscast roll request для обязательной preparation-фазы.
- Подключать triggered preparation ещё одним узким adapter над существующим `prepare_miscast`. Требовать точное совпадение post-Test actor/source roll/state; возвращать optional pre-Miscast spell и обязательный roll в книжном порядке, не исполняя их рекурсивно.
- Для interrupted Casting не встраивать magic state в конкретные action executors. Общий adapter принимает завершённый `ActionExecutionReceipt` и актуальный `WizardMagicState`, исключает typed spell Improvise, создаёт одно action-sourced увеличение Miscast Pool и применяет общий threshold. Различать provenance `TEST`/`ACTION`. До общего battle aggregate caller обязан передавать ordered snapshot уже потреблённых execution IDs; reducer добавляет текущий ID ровно один раз и отклоняет повтор.
- Добровольное прекращение уже активного Casting считать отдельным magic decision без нового action slot. При непустом пуле переиспользовать общую preparation-фазу, при пустом — очистить Casting snapshot без `MiscastRollRequest`; уже triggered pool принимает только прежний обязательный preparation path.
- Free move и его Prone-removal alternative считать incidental spatial-фазами без action slot. Composite requests используют round state только для проверки active actor и синхронизации номера round; изменяемый placement/target Condition и общий once-per-turn usage остаются вне turn state.
- Базовый Run исполнять отдельным composite adapter над зарезервированным Run slot и `SpatialBattleState`: сначала проверить и применить переход в одну соседнюю Zone, затем добавить receipt. Не помещать placement или free-move usage в turn state.
- Optional Athletics Run исполнять отдельной post-movement фазой над завершённым base result: не создавать второй receipt, на успехе менять только spatial state, а на провале применять первый Staggered. Явно запрещать её после Difficult Terrain Athletics Test того же turn.
- Базовый Medium Charge исполнять атомарным composite adapter: проверить movement context, создать spatial snapshot, выполнить одну Close Range kernel attack и лишь затем добавить receipt. Сохранять source/prepared attack requests; `+1d` добавлять только к Melee по временной политике `AMBIGUITY-007`.
- Long Charge исполнять отдельным атомарным composite adapter над тем же slot. Сначала проверить двухзвенный Long route и конфликт Difficult Terrain, затем выполнить Athletics. Success доходит до Close и вызывает kernel; failure доходит только до intermediate Zone, впервые применяет Staggered и добавляет receipt без kernel result. Обе ветви считаются исполнением Charge.
- Difficult Terrain traversal считать общим spatial reducer без собственного action slot. Он сохраняет полный source request, crossed state, Conditions и Test usage. Free move/base Run/Medium Charge consumers доказывают равенство actor/round/origin/destination/path/Conditions и current snapshots. Free move расходует usage, Run добавляет receipt без RNG, Charge выполняет kernel attack и затем добавляет receipt. Полученный Prone сохраняется и не отменяет уже начатую Charge attack.
- Move Carefully исполнять отдельным атомарным composite над зарезервированным slot и обычным terrain-aware free move. Он расходует free-move usage без terrain Test, затем либо явно пропускает search без RNG, либо выполняет один Awareness Test, и только после полного результата добавляет receipt.
- Move Quietly исполнять отдельным composite над зарезервированным slot, stable enemy observer snapshot, общим Stealth/Awareness Opposed Test и explicit decline/same-Zone/route hiding choice. Все contest outcomes завершают slot; free-move usage и hidden opportunity появляются только после победы с cover и новым hiding position.
- Hidden opportunity потреблять отдельным composite вокруг обычного Attack executor. Успешный путь обязан доказать исходный hidden result/opportunity, прежний actor placement и explicit hiding-position ID, current unaware target из stable observer snapshot, pending Attack slot и `defender_test=None`; только затем исполнять Attack и одним переходом добавлять opportunity ID в ordered consumed snapshot. Не создавать второй receipt. Profile-aware ranged вариант использует дополнительный combined contract: hidden и ranged preflight обязаны разделять один exact Attack, исполняется только ranged resolver, а opportunity погашается после его успеха. Для ухода с позиции, другой либо уже aware цели выбранного Attack возвращать отдельный loss reason без Attack и также погашать ID. Completed non-attacking action направлять в continuation: explicit departure/reveal погашают opportunity, иначе она сохраняется без изменения consumed chain. Проверять completed receipt, actor/round/порядок относительно Move Quietly; Attack/Charge/attacking Improvise требуют отдельных attack paths. Не выводить reveal из одного action kind, не создавать RNG/receipt и не изменять независимый Aim snapshot. Consumption snapshot до общего aggregate передаёт caller.
- Aim исполнять как Awareness Test по выбранному врагу и создавать отдельный bonus snapshot. Следующее действие владельца обязано погасить snapshot: только Shooting/Throwing Attack той же цели получает обычные bonus dice; любое другое действие теряет их. Не хранить snapshot внутри turn state, чтобы он мог пережить границу хода. Для profile-aware Shooting отдельный combined consumer принимает уже подготовленный `AimFollowUpResult.attack`, исполняет unified ranged resolver один раз и дописывает follow-up ID в immutable consumption chain; zero bonus тоже расходуется, а mutable bonus store не вводится.
- Help исполнять как собственный Test помогающего и связывать bonus snapshot с другим союзником, конкретными Skill и stable ID его upcoming Test. Отличающийся Help Skill требует явного решения GM; Deafened и Defenceless закрывают действие до RNG. Применение бонуса оставить отдельной одноразовой границей вне turn state.
- Recover исполнять одним adapter с закрытым выбором `STANDARD`/`TREAT_WOUND`/`REMOVE_CONDITION`. Standard atomically возвращает выбранные Condition transitions, уменьшенный Miscast Pool и external mount/object follow-ups; альтернативы не получают standard benefits. Treatment выполняет Recall либо auto-Lore и возвращает source-aware application request. Его отдельный одноразовый reducer принимает точный successful Recover result и тот же injury snapshot, отмечает одну Wound treated, снимает только её `UNTIL_TREATED` effects и удаляет общую Condition лишь по explicit no-other-source snapshot; он не создаёт второго action receipt. Automatic end-battle treatment использовать отдельный target-scoped completed-battle/catch-breath context: без action/Test/RNG он применяет тот же transition ко всем untreated Wounds при наличии trappings и однократно погашает context ID. Condition Test при успехе снимает одну Condition только после external underlying-cause gate.
- Запрещать завершение хода с любым зарезервированным, но неисполненным Aim, обычным Attack, Help, Recover, Run, Charge, Move Quietly, Move Carefully либо Skill/spell/Ability Improvise.

- Единый profile-aware ranged Attack adapter принимать union free/exacting weapon state. Free-ветвь исполняет ordinary Attack и сохраняет state, числовая ветвь переиспользует узкий reloadable composite; обе возвращают один nested Attack и один receipt. Не дублировать kernel ради обновления weapon state и не смешивать сюда hidden-opportunity consumption.

- Prepared hidden ranged consumer связывает готовую профильную preparation (включая optional Aim) с existing hidden preflight по exact final Attack. Исполнять только prepared executor, не вызывать второй hidden/ranged executor; после результата дописать hidden opportunity ID. Один nested prepared result владеет Aim chain и weapon/Attack transition; внешний result хранит отдельную hidden chain и объединённый trace. Non-Attack continuation выделен отдельно; `CODE-CONFLICT-001` исправлен. Prepared execution не является автоматическим lifecycle dispatcher.

## Последствия

Порядок боя и action economy можно тестировать без RNG, карты, injury state и старого P1 battle loop. Конкретные действия сохраняют собственные типизированные контракты. `FateSessionState` остаётся вне turn state; narrow composite атомарно расходует его для конкретного второго slot, а scheduler видит только bound proof. Ability state и связывание остальных ресурсов с scheduler остаются у будущего агрегирующего orchestration.

Срез пока не определяет Awareness-результат засады, прочие incidental actions, Tactical Retreat и другие расходы Fate, healing tiers после `CATCH_YOUR_BREATH`, применение mount/inventory follow-ups, исполнение подготовленных Miscast follow-ups, общий battle aggregate, окончание боя и AI выбора порядка. Second Action за Fate, Aim, Help, Recover вместе с application успешного и automatic end-battle treatment, отдельное `CATCH_YOUR_BREATH` healing, Skill Improvise с Prone/Distracted application-фазой, Troll Vomit, Troll Hag Swamp Breath и Forest Dragon Soporific Breath Ability Improvise, обычный и hidden Attack, обе фазы Run, Medium/Long Charge, Move Carefully, Move Quietly, standalone Difficult Terrain traversal с free-move/base-Run/Medium-Charge consumers, normal post-Casting, triggered preparation, добровольное прекращение Casting, общий skipped-Casting consequence для non-Casting action receipts и обе ветви free move уже исполняются; соответствующий slot должен завершиться до конца хода. Aim/Help/hidden-opportunity snapshots, Skill-Improvise/treatment/healing consumed IDs, остальные Recover external applications и interrupted-Casting consumed-ID snapshot остаются immutable внешними состояниями, владение которыми перейдёт future aggregate. Завершение активного хода требует зарезервировать standard action; если позднее книжный источник потребует явный pass/skip, он должен быть представлен отдельным нормативным действием или решением, а не пустым ходом.

## Уточнение 2026-09-22 — хронология hidden Attack

Общий hidden Attack request требует, чтобы его `(round, slot)` был строго позже исходной completed Move Quietly. Это source-provenance preflight до RNG для ordinary/profile-aware/prepared/registered путей. Разрешать slot 1 более позднего round; не вводить expiry opportunity на границе хода. Основание: BOOK-PLAYER-GUIDE 1.4, Rules / Manoeuvre, стр. 117. Aim next-action semantics независима.

Для same-round hidden Attack требовать точный completed Move Quietly slot/receipt в текущем attack snapshot. Сравнивать значения, не идентичность объектов; совпадения round/slot или одного receipt ID недостаточно. Более поздний round не должен переносить прежний receipt в новый turn state.

Для завершённой non-Attack потери Aim использовать отдельные AimConsumptionState и AimLossConsumptionRequest/Result. Готовый LOST и receipt связывать по actor, action ID/declaration и chronology; canonical Aim request ID регистрировать независимо от follow-up ID, чтобы переименование follow-up не обходило повторную регистрацию. Допускать второй slot исходного turn или первый slot более позднего round; первое фактическое следующее действие выбирает caller. Не переисполнять action/Test и не добавлять RNG/receipt. Истории source/follow-up допускают независимые импортированные prefixes; APPLIED и history-aware preparation подключаются отдельными шагами. Основание: BOOK-PLAYER-GUIDE 1.4, Rules / Aim, стр. 116.

Проверку погашенного Aim перед ranged preparation выполнять отдельным prepare_ranged_weapon_attack_with_aim_history(state, request): actor и canonical source ID проверяются до прежней preparation. Не менять существующие request/result, не дописывать history при подготовке, не выполнять Attack и не дублировать расчёт modifiers. Старый низкоуровневый путь сохраняется; caller выбирает adapter и актуальный state. APPLIED registration остаётся отдельным шагом. Основание: PG 1.4, Rules / Aim, стр. 116.

APPLIED Aim регистрировать отдельным consumer готового AimRangedWeaponAttackExecutionResult: exact actor/Attack/receipt и previous follow-up prefix, canonical Aim request ID плюс готовая resulting chain. Не дописывать follow-up ID второй раз и не переисполнять Attack ради history. Использовать те же AimConsumptionState и source replay guards для LOST/APPLIED; hidden/prepared wrapper передаёт исходный вложенный Aim-bound result. Hit/miss и Aim 0 разрешены. Atomic preflight/execution/registration реализован отдельным adapter. Основание: PG 1.4, Rules / Aim, стр. 116.

Для атомарного Aim-bound ranged исполнения использовать RegisteredAimRangedAttackExecutionRequest/Result и execute_registered_aim_ranged_attack. Общий с completed-result consumer preflight проверяет actor/source/prefix/chronology до единственного existing executor; затем один consumer регистрирует готовое исполнение. Result хранит только registration и предоставляет execution/state как views, сохраняя точную source/trace. Атомарность относится к возвращаемым immutable snapshots, не к откату внешних RNG/decision effects. Prepared composition подключена отдельным adapter; совместная hidden/Aim registration подключена отдельным adapter. Основание: BOOK-PLAYER-GUIDE 1.4, Rules / Aim, стр. 116.

Prepared Aim-bound Attack регистрировать через отдельные RegisteredPreparedAimRangedAttackExecutionRequest/Result и execute_registered_prepared_aim_ranged_attack. Требовать Aim и переиспользовать общий actor/source/prefix/chronology preflight через _aim_request_for до RNG. Один existing prepared executor сохраняет preparation/profile provenance; один consumer регистрирует его готовый вложенный Aim result. Result хранит prepared execution и связанную registration, не копирует weapon/receipt/history поля; state — view. No-Aim и hidden composition остаются вне adapter. Основание: BOOK-PLAYER-GUIDE 1.4, Rules / Aim, стр. 116.

Для совместной регистрации prepared hidden Attack с Aim использовать отдельные registered_hidden_aim_models/resolution, не переносить hidden зависимости в Aim consumers. Request связывает AimConsumptionState с existing RegisteredHiddenAttackExecutionRequest и принимает только prepared Aim ветвь. Общие history preflight выполняются до одного registered hidden executor; Aim consumer получает его sole nested result. Frozen result связывает hidden/Aim registrations и trace, предоставляет состояния как views. HiddenLifecycleState и проверка его актуальной active opportunity подключены отдельным adapter. Источники: BOOK-PLAYER-GUIDE 1.4, Rules / Aim, стр. 116; Manoeuvre, стр. 117; Attack Tests, стр. 118.

HiddenLifecycleAimAttackExecutionRequest/Result держать в отдельном domain module поверх существующих lifecycle и joint Aim contracts, не расширяя union lifecycle events. До RNG переиспользовать _validate_lifecycle_attack и joint history preflight. Один execute_registered_hidden_aim_attack возвращает registered hidden result, который один раз применяется через apply_hidden_lifecycle_result. Result связывает оба результата по точному source/state/completed result и объединяет trace; history/execution доступны как views. Первый выстрел recovery cycle переносит aim_state из этого результата в последующий LOST. Нового battle aggregate нет. Основание: BOOK-PLAYER-GUIDE 1.4, Rules / Aim, стр. 116; Manoeuvre, стр. 117; Attack Tests, стр. 118.

Для LOST после обычной Attack по другой цели использовать отдельный AimAttackLossConsumptionRequest/Result, не ослабляя receipt-only non-Attack consumer. Принимать completed AttackActionExecutionResult и готовый LOST; связывать actor/target/slot/previous state, Attack/kernel IDs и receipt/declaration с исходным follow-up. Истории дополнять общим immutable append helper, но сохранять отдельную trace с Attack executor. Не переисполнять action/kernel и не добавлять receipt/RNG. Same-target Melee/Brawn LOST принимается через тот же общий preflight. Atomic executor подключён ниже. Основание: BOOK-PLAYER-GUIDE 1.4, Rules / Aim, стр. 116.

Для ordinary Attack по другой цели с LOST использовать RegisteredAimLossAttackExecutionRequest/Result и execute_registered_aim_loss_attack. Общий _validate_attack_loss_preflight применяется к pending Attack до RNG и completed-result consumer; включает exact follow-up Attack и slot declaration, actor/source/follow-up history и chronology. Один existing Attack executor и один consumer возвращают sole registration; result хранит её и предоставляет execution/state как views. Не копировать kernel/receipt или histories. Исключения не меняют входные snapshots, но не откатывают внешний RNG/decision provider. Источник: BOOK-PLAYER-GUIDE 1.4, Rules / Aim, стр. 116.

Для ordinary Melee/Brawn Attack по исходной цели Aim расширить только общий target/skill guard: готовый LOST с Skill.MELEE либо Skill.BRAWN допускается без новых wrapper types. Exact Attack/receipt/chronology и history guards остаются общими с different-target ветвью; actor/source/follow-up replay блокируется до RNG. Skill берётся из типизированного follow-up, автоматического определения по оружию нет. Основание: BOOK-PLAYER-GUIDE 1.4, Rules / Aim, стр. 116; Attack Tests, стр. 118.

Brawn подключён тем же guard; общий набор тестов исполняется отдельно для обоих skills и проверяет replay между ними. Charge composition и его бонус не меняются.

LOST после ordinary Melee Charge регистрировать отдельным AimChargeLossConsumptionRequest/Result, принимающим полный ChargeActionExecutionResult. Не ослаблять receipt-only non-Attack consumer и не выдавать Manoeuvre/Charge за ordinary Attack. Общие immutable append/trace helpers допустимы; связь actor/action/declaration/receipt/chronology проверяет отдельный контракт. Готовые round/spatial/kernel states не копировать и не исполнять повторно. Atomic wrapper использует общий pending/completed preflight, описанный ниже. Основание: PG 1.4, Rules / Aim, стр. 116; Manoeuvre / Charge, стр. 117.

Для ordinary Melee Charge с LOST использовать RegisteredAimLossChargeExecutionRequest/Result и execute_registered_aim_loss_charge. Общий _validate_charge_loss_preflight принимает typed pending Charge либо completed result, нормализует action ID/исходный round state и проверяет одну и ту же history/actor/declaration/slot/chronology. Не восстанавливать pending Charge из готового результата и не исполнять его повторно. Один executor и один consumer возвращают sole registration; wrapper связывает её с исходными round/spatial/kernel states. Источник: PG 1.4, Rules / Aim, стр. 116; Manoeuvre / Charge, стр. 117.
