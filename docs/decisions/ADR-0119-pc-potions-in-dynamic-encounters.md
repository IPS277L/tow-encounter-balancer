# ADR-0119: зелья в динамическом melee-бою

Дата: 2026-11-16. Статус: принято пользователем и реализовано. Выбраны оба вида и пригодная рука без отдельного сброса.

## Проверенные источники

Gamemaster’s Guide1.1, гл.VI Magic Items, Enhancement Potion89: полностью расходуется как часть Recover, даёт +1 выбранной Characteristic до следующего заката. Healing Potion90: полностью расходуется как часть Recover, мгновенно исцеляет одну Wound и все соответствующие effects; разрешена при Defenceless, но другие actions в этот turn запрещены. Упоминание восстановления отрубленных конечностей требует своевременного применения и не задаёт численного интервала.

Player’s Guide1.4, гл.V Recover118 перечисляет standard benefits и взаимодействие с healing potion; в отличие от alternative treatment, текст зелий не отменяет standard benefits. Health121–122 определяет healed/treated, штраф следующих ран и источники Conditions. Изготовление по Concoction/GM90, downtime, покупка, неопознанные/поддельные зелья и кампания в этот срез не входят.

## Принятая граница

Подключены оба уже описываемых вида предметов в существующем dynamic inventory. Лечебное — для всех поддержанных ран текущего боя1–23, включая причинно связанные ограничения тела/рук; не воскрешает мёртвого. Оngoing Conditions от других ран, яда/сети и независимых причин сохраняются. Выпавшие предметы не телепортируются в восстановленную руку. Применение — при первой выбранной собственной возможности в этом же бою; позднее восстановление старых утраченных конечностей не моделируется.

Усиливающее — для четырёх исполняемых Characteristics: WS, Strength, Toughness, Agility. Остальные четыре остаются описываемым draft и отклоняются до trials, пока соответствующие игровые параметры не подключены. Начало — здоровые PC новой сессии, до заката; закат во время короткого encounter не моделируется. Увеличение Characteristic меняет настоящий dice pool/cap, Damage и Resilience по применимым формулам, а не даёт универсальный +1d. Drained не отменяет изменение исходной Characteristic. Первоначальное описание персонажа не изменяется.

Количество — конечный запас каждого instance ID; каждый trial получает независимую копию. Применение оставляет source-bound proof: actor/item, Recover slot, выбранная Wound/Characteristic, состояние до/после и списанная единица. Повторное применение одного proof, чужой предмет, пустой запас и stale snapshot отвергаются. Native replay хранит исходный инвентарь в текущем PC JSON1; новых ручных tactical полей в Dynamic JSON1 нет. Остальные явные PC policies не начинают пить автоматически.

## Тактика и согласованная конкретизация рук

Обычный PC сравнивает полезность разрешённого применения с Attack/Help/Recover; выбираются конкретный предмет и рана. Лечение Defenceless имеет приоритет над пропуском хода. Из нескольких ран при равной полезности выбирается большая table severity, затем более ранняя sequence; из предметов — входной порядок. Полезность усиления оценивается на ограниченном горизонте оставшихся ходов, без вложенного Monte Carlo. Точные веса остаются проверяемой эвристикой контроллера, а не правилом книги.

Выбрано добровольно использовать не более одного усиления каждой Characteristic за encounter. Это выбранная тактика экономии, не утверждение о книжном запрете складывать одинаковые зелья; общее stacking rule без отдельного источника не вводится.

Книга не определяет hand-use питья. Пользователь разрешил собственное питьё при наличии хотя бы одной пригодной руки, включая руку с оружием/щитом: Recover включает взаимодействие с предметом, отдельного сброса не требуется. Это явная scenario/GM-конкретизация. Injured Hand12 вызывает прежний Critical, если используется именно она; при доступной здоровой выбирается здоровая. Без пригодной руки не терять inventory и не расходовать ход на невозможное применение. Кормление другого PC и трактовка временного ослабления2H grip/пассивного щита вне действия не добавляются.

## Реализация

`domain.potion_models` — immutable описание запаса и точный переход лечения; application/UI не являются зависимостью domain. `PcMeleeParticipant.consumables` хранит начальные предметы, независимый runtime — оставшиеся `potions` и `enhancements`. Существующие явные роли не принимают запас зелий: этот срез назначает автоматическую тактику целиком.

`PcPotionRecoverProof` связывает выбранный предмет/рану/руку, обычный Recover receipt и полные состояния бойца до/после. Projection заново строит canonical proof из фактического owner. Object interaction занимается питьём: он не подбирает одновременно оружие/щит. При выбранном питье incidental weapon-first release/draw/swap откладывается. Вылеченная рука возвращает доступность оставшегося на ней щита; записанный DROPPED предмет остаётся на земле. Тяжёлый2H stop откладывается только при физически доступном лечебном зелье, чтобы собственный ход мог исполнить лечение.

Общий Recover получает узкое typed `HealingPotionRecoverSource` исключение для Defenceless. Оно требует собственного незажившего источника раны, наличия настоящей Healing Potion и взаимодействия именно с ней; обычный Recover по-прежнему запрещён. Для Defenceless питьё занимает единственное действие этого хода. Native автоматическая PC-политика не предоставляет второе действие.

Усиленные реальные характеристики выводятся `pc_effective_definition`: WS меняет Melee/Defence и их cap, Strength — Damage, Toughness — Endurance/cap и Resilience, Agility — Athletics/cap. Штрафы ран, Drained и оружейные Traits проходят прежние builders. Общий controller сравнивает прирост Attack/защиты усиления на горизонте до3оставшихся собственных ходов с текущим действием; на последнем ходу не пьёт ради будущих преимуществ. Лечение оценивает тяжесть/активные эффекты и возможность совместить с уже нужным Recover. Это ограниченная эвристика, не optimal AI; точные веса находятся в `pc_tactical_models`.

Trial/summary содержат `potion_use_counts` в полном исходном порядке actor/item, включая нули; без начального запаса поле отсутствует. Проверяются stock×trials, общий action/turn budget с Help/ally Recover и once-per-Characteristic тактика. Текущие PC JSON1/Dynamic JSON1, schemas и executable replays сохраняют запас и фактические расходы без новых ручных policies/версий. UI использует прежний редактор и показывает средний расход в статистике состава. [Исполняемый пример](../examples/dynamic/potions.request.json).

## Проверка

Детерминированные native случаи: списание последней единицы, выбор между несколькими предметами/ранами, healed wound больше не утяжеляет будущую; сохранение независимых Conditions и другой раны; восстановление руки без автоматического подбора; Defenceless→Recover с запретом второго действия; влияние каждого из четырёх enhancements на реальные производные и Drained; cap/minimum die; once-per-Characteristic тактика; immutable исходник/независимые trials/source forgery.

Дополнительно проверяются dynamic parser/preflight и текущие схемы/replay/result, агрегированные фактические расходы, один process parity сценарий и существующий UI с уже имеющимся редактором. Полный regression или wheel по привычке не нужны; адресный набор определяется затронутыми healing/hand/clock/Test/Fate paths. Решение о более широком regression принимать по фактическому изменению общих owners.
