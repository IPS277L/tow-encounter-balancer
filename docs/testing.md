# Тестирование

Объём выбирается по [AGENTS.md](../AGENTS.md#политика-проверок). Проверяем изменённое поведение и зависимые границы. Статус сообщает фактический результат; [подробная историческая инвентаризация](testing-history.md) читается только при поиске конкретного случая.

## Выбор проверок

| Изменение | Нужная проверка |
|---|---|
| Правило/модель | Детерминированные исходы, source/type guards и однократное применение |
| Связь компонентов | Сквозной путь через затронутые слои, результат и обязательные follow-ups |
| JSON/CLI | Строгое чтение, current schemas, полный source echo и ошибки; репрезентативные маршруты запуска |
| Process execution | Seed/source/aggregate parity и реальный spawn при изменении этого механизма |
| Документация | Согласованность и локальные ссылки; исполнение примера только при изменении его кода/контракта |
| Общая контрольная точка | Полная регрессия по основаниям; installed wheel при проверке доставки |

После исправления повторяются упавший и релевантные зависимые тесты. Не повторять успешную тяжёлую матрицу ради нового названия этапа. Не выдавать составной результат за единый зелёный полный прогон.

```powershell
$env:PYTHONPATH = 'src'
.venv/Scripts/python.exe -m unittest tests.unit.test_k1_opposed_test -v
```

## Общая подготовка тестов

Повторяющиеся builders находятся в [tests/support](../tests/support/). Например, [Magic JSON fixtures](../tests/support/magic_json_fixtures.py) дают свежий документ и явные варианты Miscast для simulation/balance. Каждый вызов независим; matching assertions balance не разделяют mutable policy object. Helper не исправляет неизвестные поля, version или malformed source.

Использовать небольшой helper при реальном повторении, сохраняя явные условия конкретного теста. Не создавать универсальный DSL и не переносить весь test suite ради единообразия. Ожидаемый игровой результат задаётся независимо от production-алгоритма. Существующие wrappers в test modules сохранены там, где от них зависят imports.

Public example добавляется для значимой пользовательской возможности; внутренний переход обычно проверяется в unit/integration. Собственный copied probe, audit document и wheel для каждого правила не обязательны. Monte Carlo не проверяет точное значение вероятности.

## Контрольная точка проекта

Полный набор, только при основании из политики:

```powershell
$env:PYTHONPATH = 'src'
.venv/Scripts/python.exe -m unittest discover -s tests -v
```

Import-only discovery проверяет доступность модулей и helpers, но не считается исполнением тестов. Исторические результаты и known errors остаются в соответствующих ADR/аудитах.
