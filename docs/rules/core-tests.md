# Базовые проверки

Источники: `BOOK-PLAYER-GUIDE`, преимущественно страницы 106–110; `BOOK-GM-GUIDE`, версия 1.1, страницы 64–65. Статус базового kernel: `implemented`; Help, Fate, общий Exacting lifecycle и GM-side task selection ещё расширяются отдельными срезами.

## RULE-DICE-001 — обозначения d10 и d100

Один `d10` даёт значение от 1 до 10; грань `0` читается как 10. Несколько d10, записанных как `Nd10`, бросаются вместе и суммируются, если конкретное правило не предписывает считать успехи. Для `d100` заранее различаются десятки и единицы; две грани `0` дают 100.

Источник: Player’s Guide 1.4, Introduction, страница 11. Статус: `partially implemented`: общий RNG и суммирование d10 используются Wounds/Miscast, но отдельного d100-контракта пока нет.

## RULE-TEST-001 — профиль проверки

Проверка использует одну характеристику и один навык. Значение характеристики определяет исходное количество d10, значение навыка — максимальный результат куба, считающийся успехом.

Источник: страницы 106–107, 68.

## RULE-TEST-002 — базовый успех

Обычная проверка успешна, если получен хотя бы один успех. Качество Basic Test: `0` — Failure, `1` — Marginal Success (обычно GM добавляет уместную Complication, но может продолжить без неё, если подходящей нет), `2` — Success, `3+` — Total Success (игрок может предложить дополнительный положительный эффект в разумных пределах).

Complication не отменяет успех; слишком высокую цену игрок может отвергнуть, выбрав провал. Эти дополнительные последствия опциональны и не применяются к Help, Attack или Exacting Tests, где число successes уже имеет другую функцию.

Источник: Player’s Guide 1.4, страницы 106–108; Gamemaster’s Guide 1.1, страница 65.

## RULE-TEST-003 — модификаторы пула

Обстоятельства, помощь, способности, раны, состояния и снаряжение могут добавлять или убирать кубы. Если специальное правило не говорит иначе, итоговый пул не может превышать удвоенное значение используемой характеристики.

Если после модификаторов осталось меньше одного куба, всё равно бросается один d10, но успехом считается только `1`. Естественный пул ровно из одного куба не включает это ограничение и использует обычный порог Skill.

Источник: страница 107.

## RULE-TEST-004 — Grim и Glorious

- Grim заставляет один раз перебросить все первоначальные успехи.
- Glorious разрешает один раз перебросить первоначальные неуспехи.
- Grim и Glorious не суммируются сами с собой и взаимно отменяются.
- Повторно перебрасывать уже переброшенный куб нельзя.

Источник: страница 108.

## RULE-TEST-005 — помощь

Помогающий выполняет собственную подходящую проверку. Каждый его успех добавляет один куб к проверке получателя помощи.

Источник: страница 108; боевое применение уточняется на странице 117.

## RULE-TEST-006 — встречная проверка

Обе стороны выполняют проверки, побеждает сторона с большим числом успехов. Общие ничьи разрешаются инициатором, стороной, меняющей текущее положение, либо более высоким навыком. В атаке ничья всегда принадлежит атакующему.

Если обе стороны получили ноль успехов, обе проверки неуспешны и обычный tie-break не применяется.

Источник: страница 109.

## RULE-TEST-007 — Exacting Test

Exacting Test накапливает successes нескольких Basic Tests до заданной GM цели. Участвовать могут несколько персонажей; каждая Test имеет цену во времени, Coin/ресурсах, риске или favour. В high-pressure ситуации цена обычно состоит в потраченном turn/action; без значимой цены следует использовать Basic Test.

Если отдельный вклад Opposed, progress равен successes участника минус successes противника. Победа только по tie-break даёт `1` progress. Провал никогда не уменьшает уже накопленный итог, а лишь не продвигает его. Книга приводит ориентиры `4` successes для заметного обязательства, `8` для тяжёлого испытания и `12+` для особенно трудной задачи.

Источник: Player’s Guide 1.4, страницы 12 и 110. Статус: `draft`: накопление Casting successes уже представлено узким магическим состоянием, но общего multi-contributor/cost lifecycle пока нет.

## RULE-TEST-008 — когда и как GM назначает Test

Test назначается, когда исход одновременно находится под сомнением, применяемый Skill способен повлиять на него, а возможные результаты драматически или практически значимы. Очевидное, невозможное для данного действия либо несущественное действие не требует броска.

Типовые difficulty modifiers: `-1d` для Difficult и `-2d` для Very Difficult. Подходящий Lore или созданное игроком преимущество может дать bonus dice; конкретное значение остаётся входом сценария/GM policy. Вне Talents и явных правил Grim или Glorious применяются лишь при подавляющем неблагоприятном либо благоприятном сочетании обстоятельств. Эти оценки нельзя скрыто выводить в kernel из художественного описания сцены.

Источник: Gamemaster’s Guide 1.1, страница 64.

## Реализация K1

- контракты: `src/towr/domain/test_models.py`;
- Basic Test и общий roll pipeline: `src/towr/rules/test_resolution.py`;
- Opposed Test: `src/towr/rules/opposed_test.py`;
- детерминированные проверки: `tests/unit/test_k1_test_resolution.py` и `tests/unit/test_k1_opposed_test.py`.

K1 хранит исходные значения, перебросы, итоговые успехи и Rule ID применённых модификаторов в `RollTrace`. Добровольные перебросы Glorious требуют явного `TestDecisionProvider`; скрытого решения kernel не принимает.
