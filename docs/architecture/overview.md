# Архитектура

Этот обзор описывает актуальные слои и инварианты. Подробная [хронология](overview-history.md) и [ADR](../decisions/) читаются только для соответствующего решения. Текущий функциональный scope и следующий шаг — в [статусе](../project-status.md).

## Направление зависимостей

```text
CLI / JSON / future GUI
          |
          v
 application services
          |
          +---------> balance
          |              |
          v              v
       engine <----- simulation
          |
          v
        rules
          |
          v
        domain
```

Внутренние слои не импортируют CLI/JSON/GUI или балансировщик. Application связывает вход, generation, simulation и агрегированный результат; адаптеры только отображают внешний формат и ошибки.

M54 по [ADR-0099](../decisions/ADR-0099-pc-pistol-and-exacting-reload.md) связывает PC Shooting с существующими ranged preparation/weapon-instance primitives. Owner хранит typed shot/Reload proofs, актуальные loaded/progress/cycle и полный Fate prefix. Reload занимает обычный Improvise/Skill slot. Чистое завершение после готового Test находится в domain/reload_models; rules и engine вызывают его без повторного RNG, domain не импортирует rules. Source/profile отделён от состояния экземпляра. Admission воспроизводит canonical prefix, проверяет однократный расход и не принимает cached result за сохранённую игру. Предметный source и пользовательский вход — в [примере](../examples/m54/README.md).

M55 по [ADR-0100](../decisions/ADR-0100-pc-pistol-shield-reload-priority.md) объединяет существующие Pistol/shield states без нового proof type или wire field. Общий hand selector запрещает shield pickup при empty Pistol и для выбора Recover, и для его object interaction. Release выбирается непосредственно перед доступным Reload после необходимого восстановления; actual HELD guard освобождает руку без удаления dropped предмета из owner. После completion возвращается прежний shield Recover. Полный prefix подтверждает обе перестановки и отдельные action receipts.

M56 по [ADR-0101](../decisions/ADR-0101-pc-close-shooting-npc-protection-choice.md) хранит optional actor→Skill policy в source сценария. Factory связывает полный canonical NPC с проверенным Melee/Athletics profile, owner выбирает его лишь против Shooting. Definition.protection сохраняет обычную Defence от Melee, общий K1Protection уже умеет Close ranged Melee opposition. Generation удаляет записи исключённых actor без переназначения и передаёт отсутствие вместо пустого списка; полный template проверяется раньше. Canonical replay связывает policy/actor/actual Test без нового proof variant или action.

## Инварианты

- Определение существа отделено от состояния экземпляра и состояния конкретного боя. P1 `CombatantDefinition`/`BattleEngine` — прототип, а не универсальная реализация книги.
- [Resolution kernel](resolution-kernel.md) исполняет один Test/Attack/effect; orchestration отвечает за порядок, action slots и follow-ups. Не добавлять универсальный язык правил или event bus.
- RNG передаётся явно. Trial получает собственный поток; воспроизводимость зависит от input/seed/runtime, а не глобального random state.
- Prepared request, result, receipt и journal witness связываются с полным источником. Совпадение ID или равенство projected state не заменяет admission исходного объекта. Результат применяется один раз к актуальному owner.
- Mandatory continuations разрешаются до обычного следующего действия. Неизвестные GM facts и неподдержанный обязательный путь дают явный stop, а не выдуманный игровой исход. UNSUPPORTED_PATH остаётся в знаменателе trials.
- Повторная Attack M39 требует узкий `EnduringStrengthGrant` с actual first receipt и другой разрешённой целью. Clock проверяет структуру и максимум двух действий; PC owner подтверждает полный первый HIT, canonical Bear, caller policy и завершение последствий. Вторая Attack имеет свой slot/receipt/Test IDs; TurnEnd остаётся один. [ADR-0087](../decisions/ADR-0087-pc-bear-second-attack-policy.md).
- M42 хранит Brewguard Distracted в owner-local typed source/focus bank, не меняя generic ConditionState. Profile ACK подтверждает реального первого attacker; отдельный expiry proof ссылается на completed Wound/Fate либо Critical death source. Mandatory expiry предшествует следующему Test и terminal result; kernel получает готовые Melee/Protection modifiers. [ADR-0088](../decisions/ADR-0088-pc-brewguard-distracted-focus.md).
- M43 добавляет в этот bank отдельный Miner encounter source: обязательные пары из source подтверждаются initial proofs до первого хода. Grudge Melee bonus выводится из relationship независимо от текущего Condition; Brewguard W1 cause не переиспользуется. Subset generation фильтрует пары по оставшимся NPC, не создаёт новые связи. [ADR-0089](../decisions/ADR-0089-pc-miner-grudge-policy.md).
- Балансировщик использует общий бюджет, вход симулятора и агрегаты. Report/cache/source chain проверяется до пересоздания derived данных; encoder не переигрывает trials.

- M44 отделяет представление Protection Skill от разрешения выбора: Stealth требует typed Now You See Me permission с полным canonical Thief и defender ID. Unaware/Defenceless precedence сохраняется; PC owner связывает разрешение с actual target в replay. [ADR-0090](../decisions/ADR-0090-pc-halfling-stealth-protection.md).

- M46 подтверждает voluntary Blood Rage отдельным pre-Test proof. Однократный Bestigor Glorious выводится из actual W1 ACK и следующего собственного Attack в history, не из оставшейся W1/нового раунда. Attack proof сохраняет typed source, replay проверяет quality/rerolls и consumption. [ADR-0091](../decisions/ADR-0091-pc-bestigor-blood-rage-and-wound-glorious.md).

- M47 связывает first-Staggered replacement с typed K1 spec до incoming Attack; own-miss Wound имеет отдельный actor/source proof. NPC self Recover использует обычный action receipt и отдельно подтверждённое profile heal, с собственными costs. Unbreakable остаётся точечным правилом Broken, не psychological immunity. [ADR-0092](../decisions/ADR-0092-pc-flagellant-feel-no-pain-and-recover.md).

- M48 хранит отдельную finite end phase Skin Wolf: cost/heal activation, ordered target snapshot, target Stagger receipts/ACK и phase end до TurnEnd. NPC pending owner допускается только с настоящим wave target source; PLAYER Fate/body queue сохраняет конкретного PC. Волна не Attack и не дополнительное действие. NPC-caused W1 имеет отдельные Brewguard/Bestigor causes; NPC focus снимается только по actual killed ACK. Compact counters отделены от action costs. [ADR-0093](../decisions/ADR-0093-pc-skin-wolf-warped-form-end-phase.md).

- M50 проверяет canonical effective target после K1 pre-Stagger Prone до выбора Staggered и actual Wound source. Near Miss сохраняет раннее Condition, ordinary Recover снимает его без автоматического возврата из истории. Post-Damage Drained остаётся отдельным источником с прежним retention bank. Existing Bear grant/counters расширены на второй canonical loadout без нового clock механизма. [ADR-0095](../decisions/ADR-0095-pc-bear-crushing-weight-pre-stagger-prone.md).

## Текущие внешние и игровые границы

Magic поддерживает только JSON6: [контракт](../decisions/ADR-0063-single-current-magic-contract.md), [публичные примеры](../examples/m8/json/README.md). Шесть request/result/error схем используют общий offline definitions file. Прежние wire formats удалены. Другие families имеют собственный единственный формат1.

Generation требует независимые matching family permissions и передаёт полный authored source в каждый допустимый subset. Arithmetic preflight не строит огромные коллекции; factory отдельно проверяет полный source и actual projections.

M8 — ограниченный Wizard/Curse сценарий с opt-in продолжениями. Для текущей Battered Leg границы важны [owner invariants60](../decisions/ADR-0060-battered-leg-owner-bridge.md), [native journal61](../decisions/ADR-0061-native-battered-leg-continuation.md) и delivery62, superseded только в части wire compatibility решением63. [Free self-stand64](../decisions/ADR-0064-battered-leg-prone-removal.md) хранит один bound stand в completion witness; собственный native prefix подтверждает его членство. Gate принимает точную injury после этого перехода, сохраняя stop для новых последствий. Standard self Recover также использует отдельный bound action proof в том же witness/history; расходует action slot и связывает уменьшение Pool с post-action skipped Casting. Allied removal пока не реализован. Полный каталог, arbitrary injury combinations, общий campaign loop и save/resume не следуют из наличия отдельных K1 consumers.

M9 вводит отдельные [PC input](../../src/towr/domain/pc_melee_models.py) и [battle owner/journal](../../src/towr/domain/pc_melee_result_models.py) по [ADR-0065](../decisions/ADR-0065-first-pc-melee-encounter.md). NpcDefinition не принимает PLAYER; PC использует Characteristics/Skills и PLAYER Wound lifecycle. В одном owner находятся общий clock, PC/Fate/daily state, Minion snapshots и источники последствий. Чистая проекция шагов проверяет actual K1 proofs и полный prefix, engine исполняет Attack/Recover/mandatory work. Independent trials отбрасывают journal, balance получает aggregate-only данные и перебирает bounded counts. PC имеет отдельный текущий JSON1/CLI; inverse compatibility с P1 или подмена PC Champion не вводятся. Общая inventory/campaign модель из этого bounded owner не следует.

Новые правила реализуются законченной функцией через нужные слои в рамках существующих инвариантов. Отдельный ADR создаётся при новом выборе или изменении границы, а не автоматически на каждый слой реализации.

M10 по [ADR-0066](../decisions/ADR-0066-pc-party-melee-encounter.md) расширяет тот же PC owner до uniform `party`, включая одиночную группу. Все участники имеют собственные definition/Fate/injury/daily/weapon/expiry; общий clock и journal определяют их взаимодействие. Pending PLAYER work содержит actor-владельца, а завершённая смерть исключает только погибшего. Ни временная подмена source, ни запуск отдельных дуэлей не используются. В compact trial остаются source-ordered IDs подтверждённых потерь; aggregate содержит per-PC counts и количество trials с потерями, включая observed prefix остановленного боя. Balance фиксирует всю party и проецирует enemy priority/defeat decisions каждого PC. Текущий PC JSON1 использует только uniform party shape; старый одиночный формат удалён.

M11 по [ADR-0067](../decisions/ADR-0067-pc-melee-profile-brutes.md) допускает static numeric Minion/Brute в том же owner. Target injury policy и предел происходят из полного NPC definition; `PcProfileWoundProof` подтверждает любой actual profile change. Nonterminal Wound сохраняет actor, terminal требует caller/GM defeat disposition; profile count не подменяет PLAYER lifecycle. Wire явно хранит policy/limit, generation сравнивает полный definition и фильтрует те же authored snapshots. Нового симулятора, версии wire или универсального описателя on-Wound behaviours нет.

M12 по [ADR-0068](../decisions/ADR-0068-pc-heavy-wound-continuation.md) хранит закрытые body facts и обязательные consequences каждого PC/Wound sequence в том же owner. End phase имеет bound Endurance/decline/результат и source-aware expiry; `PcIncapacitatedTurnEndProof` завершает настоящий actionless Defenceless turn, не подделывая standard action. Pure K1 Critical consumer не управляет RNG/clock/daily. Общий kernel выбирает forced Wound из фактического Damage Attack и target conditions/restrictions; признак physical_attack задаёт caller, а не выводится из numeric Damage. Canonical projections проверяют полные request/result types, prefix и обязательный Critical tail даже при последнем NPC defeat. Campaign/save и универсального body/inventory языка нет.

M13 по [ADR-0069](../decisions/ADR-0069-pc-near-miss-policy.md) сохраняет начальный Fate в source и разрешает текущему owner изменять его только фактическими lifecycle Near Miss proofs. Общий builder связывает включительный порог таблицы, резерв rating, текущий actor/roll и consumed history. Near Miss применяется до daily/effects/death; RNG повторно не исполняется. Compact trials/summary показывают только новые burns в полном порядке party, без переноса journal в balance. Перед извлечением observations проверяется полный result; cached ресурс не становится доверенным числом по одному ID или длине списка. В текущем PC JSON1 обязательный `near_miss_policy` явно связан с выбранной стратегией, остальные Fate options остаются declined.

M14 по [ADR-0070](../decisions/ADR-0070-pc-glorious-test-policy.md) добавляет отдельную Glorious configuration и общий mode `configured`, заменяя Near Miss-only имя. Pure PC selector/validator связывает собственный initial roll, навык и актуальные remaining spends с полным K1 spend proof; owner учитывает spend до последующего burn. Original Attack/Protection source сохраняется, effective Test получает только подтверждённый modifier. Общий `_resolve_attack_after_tests` завершает прежнюю арифметику без нового RNG. Все PC Tests, включая Wound/Critical/actionless end phase, используют один принцип. В compact/summary новые Glorious расходы отделены от Near Miss и supplied истории; balance остаётся aggregate-only. Текущая JSON1 требует обе nullable policies, прочие optional Fate uses остаются declined.

M15 по [ADR-0071](../decisions/ADR-0071-pc-melee-help-policy.md) добавляет `PcHelpProof` настоящего standard action и source-bound `help_applications` у намеченной PC Attack. Новой изменяемой очереди бонусов нет: applications строятся из точных предшествующих Help receipts того же owner и Test ID. Zero/multiple/capped/unused snapshots не теряют происхождение; старые бонусы не переназначаются другому actor/Test/round. Pure `_expected_help_execution` завершает прежние slot/bonus/clock transitions по actual Test, без RNG и зависимости домена от rules. Glorious/hand Critical/next-Test effects/end phase используют общий PC механизм, а clock PC-side→NPC-side сохраняется. Compact summary считает actual Help actions отдельно от Fate; generation фиксирует helper/beneficiary роли. Текущий PC JSON1 требует nullable `help_policy`.

M16 по [ADR-0072](../decisions/ADR-0072-pc-protection-help-policy.md) задаёт в Help configuration явные target и Protection Skill. Тот же generic application builder работает с actual attacker либо defender Test, связывая beneficiary/Skill/Test ID и всю предшествующую цепочку. Для Protection выбирается первый текущий live NPC при совпадении ожидаемой цели; original Protection options сохраняют Help до собственного Glorious. Equipment/target change, killed NPC и no-Test Defenceless оставляют snapshot unused. Выбор не хранит NPC ID в authored party, поэтому count projection не переписывает Help configuration. Новых owner banks, RNG, metrics или wire version нет.

M17 по [ADR-0073](../decisions/ADR-0073-pc-ally-standard-recover.md) оставляет один `PcRecoverProof`, но canonical standard choices могут затрагивать разные PC. Shared pure completion собирает прежние slot/clock receipts, PC projection применяет каждую change к её entity и сохраняет unrelated injury/Fate/daily/body. W13 consequence принадлежит поднятому получателю; receiving aid не является его действием14/15. Источники ongoing Conditions проверяются до выбора целей. Compact observations отдельно считают actual nonself Recover actions после exact result/journal admission, не число effects; source/turn/opening-round и joint support-action bounds проверяются в typed models. Role/beneficiary фиксируются в count search; текущий JSON1 требует nullable ally policy.

M18 расширяет существующую подготовку PC шестью одноручными Close weapons через [явные helpers](../../src/towr/domain/pc_weapon_models.py). Actor traits применяются к своему Test, targeted Warhammer trait — к actual Attack, Axe — отдельным DamageModifier без изменения Resilience. Каноническая проекция учитывает тот же полный impact spec/trace. [Нормализованная граница](../rules/equipment.md#исполняемая-pc-граница-m18) сохраняет прежние owner/hand/Help/Fate/Recover и JSON1, без нового языка правил, метрик и слоя inventory.

M19 по [ADR-0074](../decisions/ADR-0074-pc-two-handed-close-weapons.md) отделяет `PcTwoHandedGrip.BOTH` от анатомического `PcWeaponHand`. Прежнее поле initial_weapon_hand и state marker принимают соответствующий оружию тип, не расширяя randomised sides. Две пригодные руки проверяются для применения; whole-item drop и Critical12 учитывают обе. После полной Wound queue16/18/20 canonical owner возвращает source-bound unsupported, запрещая последующие journal steps; переноска после этой границы не моделируется. Trials/search/JSON1 сохраняют хват и прежние метрики.

M20 по [ADR-0075](../decisions/ADR-0075-pc-backup-weapon-policy.md) хранит nullable backup policy в immutable participant и однократный using_backup_weapon в боевом состоянии. Отдельный canonical draw proof подтверждает own-turn incidental transition до standard slot и фактические Critical последствия без RNG/clock/action count. [Общие selectors](../../src/towr/domain/pc_backup_weapon_models.py) задают active weapon/grip/item ID для Damage/Traits/Protection/Help/Recover. Primary не переписывается, возврат к нему не выполняется; pickup не смешивает предметы. Текущий JSON1 требует nullable policy, count search фиксирует её вместе с party.

M21 по [ADR-0076](../decisions/ADR-0076-first-pc-book-npc-catalog.md) добавляет [typed book combat catalog](../../src/towr/domain/pc_npc_catalog.py) с независимыми factory graphs и metadata неактивных способностей. Native/JSON продолжают получать полные numeric definitions; известные root/nested book identities проверяются against fresh canonical data при source admission. Authored profiles вне reserved IDs не требуют canonical graph construction. NPC Athletics/Defence передаётся actual Protection preparation и хранится явно в текущем JSON1; поиск сохраняет definition/Skill без нового owner/RNG/метрик.

M22 по [ADR-0077](../decisions/ADR-0077-pc-brigand-craven-opportunist.md) добавляет canonical Brigand Axe loadout и первый активный NPC эффект через [явный helper](../../src/towr/domain/pc_npc_ability_models.py). Текущий owner сначала считает пригодных бойцов и проверяет GM approval, затем получает один обычный или заменяющий Craven modifier; прежний Drained filter применяется после. Metadata active/inactive Abilities и unselected Warbow описывает выбор, но не является исполняемым языком. Full request/journal и source guards сохраняют источник/величину эффекта. Wire/clock/RNG/метрики не меняются.

M23 по [ADR-0078](../decisions/ADR-0078-pc-official-first-wound-broken-boundary.md) применяет Official first-Wound Broken на existing profile ACK через [pure helper](../../src/towr/domain/pc_npc_wound_models.py), сохраняя shared K1. Отдельный native NPC unsupported variant связывает actual parent Attack/target/Brute0→1 receipt; PC table fields ему не приписываются. Stop определяется только на границе следующего собственного Broken turn после очередей/end phases, до TurnStart, не сразу при появлении Condition. Обычные terminal/budget outcomes и прежние PC stops сохраняются. Wound-band metadata описательна; route/Recover не исполняются.

M24 по [ADR-0079](../decisions/ADR-0079-pc-broken-npc-adjacent-exit.md) добавляет отдельный source-bound FreeMovement proof и вывод NPC из encounter. Actual exited IDs выводятся из журнала; injury/definition не подменяются defeated. Turn/target/outnumbering/Help используют оставшихся в arena. Trials передают в агрегаты source-ordered exit counts и совместный success-with-exit count; балансировщик не получает spatial journal. Current PC JSON1 требует nullable route policy и новые метрики, прежняя null-policy stop boundary сохраняется.

M27 по [ADR-0080](../decisions/ADR-0080-natural-melee-attacks-and-creature-chunk.md) допускает явное hands=None в общем NpcAttackProfile только для natural Melee. PC boundary связывает его с unarmed fresh state/Athletics; actual target equipment передаётся Protection preparation. Wolf Give Ground ban вычисляет явный catalog helper при подготовке kernel request, а не меняет world facts. Current PC JSON1 передаёт обязательный null; остальные bounded families сохраняют enum-only admission/encoding guards. [Три unmounted профиля](../rules/npc-profile-catalog.md#natural-creatures-m27) используют существующий owner/журнал/подбор без новой шины правил или нового inventory.

M29 по [ADR-0081](../decisions/ADR-0081-pc-on-hit-drained-and-independent-condition-sources.md) хранит independent hit-condition sources в runtime PC participant, отдельно от Wound effects. Canonical PC Attack projection сверяет готовые K1 on-hit applications и связывает cause с actual Attack/target/rule; pending raw Wound сохраняет свой исходный roll, current condition state входит в completion/Near Miss. Центральная party update удерживает уже подтверждённые hit-причины после legitimate expiry/Fate, а admission отвергает malformed flags/banks. Сцены без secondary effects не сканируют историю для пустого банка; сцены с effects выводят causes один раз на state и фильтруют по target. Current PC JSON1 явно передаёт поддержанный descriptor; балансировщик получает прежние агрегаты после native readmission.

M31 по [ADR-0082](../decisions/ADR-0082-pc-goblin-melee-chunk.md) вводит explicit MinionStaggerDefeatSpec/Cause/Result для Dirty Coward. ProfileInjuryState.defeat_cause=None сохраняет прежний Wound-limit invariant; только typed zero-Wound Minion cause допускает иной defeat. K1 не подменяет его Wound или repeated-Staggered choice. PC journal отдельно подтверждает actual cause и однократный drop, сохраняет shield и исключает defeated actor без Broken exit. [Source bank](../../src/towr/domain/pc_minion_defeat_models.py) выводит разрешённое изменение оборудования из actual Attack/ACK; старые сцены без этих profiles сохраняют fixed-equipment путь. Backstabba подготавливает multiplier2 только для фактического unopposed Attack. PC JSON1 явно передаёт holds_shield и melee range_max; public source остаётся fresh/healthy, runtime cause не становится save-resume контрактом.


M33 по [ADR-0083](../decisions/ADR-0083-pc-npc-automatic-help-policy.md) отделяет no-Test automatic Help от прежнего Test-based Help: настоящий action slot и typed bonus/application receipts без фиктивного TestResult. [PC policy](../../src/towr/domain/pc_npc_help_models.py) выбирает helper/позднего ordinary attacker по явным source mappings, canonical projection проверяет source/rule/clock/exact Test binding. M34 по [ADR-0084](../decisions/ADR-0084-pc-greenskin-automatic-help.md) различает два конечных эффекта: uncapped DiceModifier и free-success SuccessModifier. Приложения обоих видов восстанавливаются по реальным receipts; Test trace проверяет rolled/success_delta/final successes. Поздний Drained filter удаляет только положительные dice modifiers. Generation удаляет mappings с отсутствующим endpoint без переназначения; отдельные source-ordered NPC Help costs проходят compact records/summary/JSON, не смешиваясь с PC metrics. Все source policies обязательны и в Python, и в JSON; при пустом tuple/list остаётся прежний Attack. Поддержаны Peasant/FCM/Goblin/Night Goblin/Orc Boy/Big ’Un; definitions прежние, тип эффекта следует из canonical book source, wire fields не добавлены.

M35 [добавляет Cultist/Elf Militia/Ungor](../rules/npc-profile-catalog.md#minion-chunk-m35) тем же data/helper путём: modifier helper получает обязательные Conditions фактической цели для Ungor Primal Spite; Cultist включён в тот же source-bound dice Help registry. Elf back-rank trigger остаётся вне all-Close/noMove admission. Нового слоя/owner/формы контракта не вводится.

M37 по [ADR-0085](../decisions/ADR-0085-pc-devour-and-wound-rage.md) передаёт actual own-Wound count для ordinary rage и actual pre-Attack target injury для Devour. Owner выводит WoundDiceModifier и связывает с KernelAttackRequest; прежний Kernel/Wound/Fate pipeline сохраняет source через direct/repeated-Staggered/Defenceless/Near Miss. Table modifier отделён от Test dice/cap/Drained, post-Damage Conditions не пересчитывают eligibility. Нового mutable банка/языка Ability/wire fields нет.

M38 по [ADR-0086](../decisions/ADR-0086-pc-minotaur-greataxe-pool-cap.md) разрешает existing InlineProfile.pool_cap=8 только canonical Greataxe attack; Protection/остальные sources требуютNone. Printed3d отделены от maximum8 в самом описании бойца; общий Test resolver использует готовый maximum без специального Greataxe override/повторного penalty. Schema enum:[null,8], codec прежний; typed domain readmission и полная canonical source проверка ограничивают применение значения.

M51 по [ADR-0096](../decisions/ADR-0096-pc-great-stag-crown-and-trample.md) добавляет отдельный CrownOfAntlersGrant в существующий clock. Узкий grant хранит actor/round, slot1 execution receipt, исходную/выбранную цель и профиль Trample; [owner](../../src/towr/domain/pc_crown_models.py) доказывает новый Prone именно от accepted Wound/failed Endurance первой Antlers Attack после mandatory tails. Bear grant остаётся отдельным типом. Slot2 выбирает второй полный canonical профиль, Brawn5d3/Damage5; PC Protection использует Endurance, а не Melee Defence. TurnEnd закрывает возможность Crown даже при смерти последнего PC. Conditional JSON secondary существует только у Great Stag; общего multi-attack DSL/source допуска нет.

M52 по [ADR-0097](../decisions/ADR-0097-pc-weighted-net-and-carried-spear.md) разделяет numeric Damage и primary Condition в NPC profile. Optional armoured metadata сохраняет printed armour при Resilience=Toughness; другие family admissions/encoders отвергают неподдерживаемый explicit metadata вместо потери при echo. PC owner выводит finite Net stock из actual Attack receipts и free draw proofs, сверяет equipment/available IDs и хранит независимые Net causes Burdened. Старые сцены сохраняют прежние source/агрегаты; conditional wire поля доступны только новому Net/Spear loadout. Brawn Recover и универсальный inventory engine не вводятся.

M53 по [ADR-0098](../decisions/ADR-0098-pc-shield-and-hand-equipment.md) добавляет optional PC shield loadout и held/dropped/unavailable runtime state. Body proofs меняют настоящий предмет выбранной руки; own-turn release освобождает руку до weapon swap/pickup. Standard Recover имеет один object interaction и возвращает weapon либо shield. Dynamic Resilience/Protection/Sword Trait используют актуальные руки до Attack, без ретроактивного пересчёта Damage. Actual skill prediction связывает Protection Help с Net/Shield/Trample; full-prefix admission отвергает возврат защиты без receipt. Старые JSON без shield поля сохраняются, generic inventory/save-resume не вводятся.
