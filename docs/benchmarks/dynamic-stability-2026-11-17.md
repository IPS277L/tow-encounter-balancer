# Устойчивость динамического поиска после ADR-0130

Дата: 2026-11-17. Статус: контрольная серия672trials и один полный UI-контроль436trials завершены. Production во время измерений не менялся.

## План до измерений

Три существующие демонстрационные партии из `tools.benchmark_dynamic.benchmark_input`: melee, mixed, mixed-magic. Для каждой master seed42и202; цели50%побед игроков и5started rounds, NPC1–10, max_rounds15, process/4. В каждой6×8screening +2×32independent validation =112trials, всего672. Это одинаковый ограниченный план для сравнения партий/seed, не полный автоматический план UI и не подтверждение его точности.

`melee` содержит2PC и явное ограниченное пространство NPC из `search.request.json`: WS/S/T2–4, Staff/Dagger, без Talents. `mixed` содержит2PC и автоматическое пространство, `mixed-magic` добавляет третьего PC — мага (Wizard) — с автоматическим пространством. Поэтому сравнение между случаями не изолирует влияние одной магии/стрельбы: это разные полные пользовательские входы. Чистое сравнение seed внутри одного случая сохраняет одинаковые party/search-space facts. Restricted melee не выдаётся за default UI envelope.

Входы предварительно допускаются текущим JSON1. Подробные source/results/batches, время и hashes сохраняются в `.cache/dynamic-stability-2026-11-17/` и `.cache/dynamic-stability-2026-11-17.json`; это developer artifacts, не новый публичный API. Других тяжёлых прогонов одновременно нет. Старые результаты до [ADR-0130](../decisions/ADR-0130-automatic-pc-recover-with-no-usable-hands.md) не используются как текущий reference для исходов.

До серии фиксируются показатели:

- У рекомендованного состава: absolute win-target distance, error длительности, Wilson95для побед, интервалы раундов, число NPC и независимых validation trials. Описательные ориентиры — point estimate в±10п.п. от50%и длительность в±1раунд от5; это не статистический допуск истинной вероятности.
- Между seed: размах point estimates/численности и число попаданий в оба ориентира. Разные seed создают разные составы: это устойчивость всего поиска, а не повторная оценка одного и того же боя.
- У выбранного финалиста: screening→validation изменение оценки на том же составе и перестановка рангов. Screening8иvalidation32дают широкую неопределённость; не выбирать стратегию по одному удачному seed.
- Во всех trials: round-limit/unsupported с исходным знаменателем, составы без рекомендации, proposal limit и затраты. Unsupported не переводится в проигрыш или победу; действующая граница исключает такой состав из рекомендаций.

Два seed на партию не доказывают общий оптимум или распределение качества. Разброс между seed смешивает различия составов и шум конечной validation. Wilson95 относится к отдельному кандидату; выбор лучшего финалиста по тем же validation данным не создаёт95%гарантии рекомендации/ранжирования. Интервал длительности — Hoeffding для started rounds с censored prefix, включая round limit.112trials — верхний план: при недостатке допустимых кандидатов фактическая validation может быть меньше. Исходы разных составов не объединяются в общую «вероятность побед».

Следующий шаг выбирается по заранее заданному порядку: воспроизводимый execution failure/отсутствие рекомендации из-за unsupported; затем повторяющиеся screening→validation расхождения как основание равнобюджетной проверки allocation; затем устойчивый duration-промах при близком win target как основание анализа score. Один плохой seed или NPC=10 не доказывает слабость алгоритма/недостижимость цели. Результат серии должен дать наблюдаемый следующий шаг; механика и budget не подгоняются после просмотра первой строки.

### Что ограничивает короткий поиск

- Melee202 проверил counts `[3,4,2,5,4,4]`, mixed-magic202 — `[3,4,3,5,5,6]`; каждый screening дал8/8побед, оба финалиста каждого поиска —32/32. Среди оценённых составов нет варианта около цели50%. Дополнительная точность или перестановка этих же финалистов не расширяет набор проверенных составов.
- Screening noise отдельно заметен: у выбранного mixed42 оценка7/8→20/32 (−25п.п.), у mixed-magic42 —4/8→23/32 (+21.875п.п.). Validation сменила первого финалиста в melee42/mixed42, всего2из6поисков.
- Все средние длительности включают censored prefix. В mixed2028round-limits:3в screening и5в validation (4у выбранного состава). Ещё1в mixed42 screening. Ни один лимит не считается победой.
- Изменение только финального score не создаст состав, попадающий в оба ориентира: такого нет среди12проверенных финалистов. Данных для смены принятого win→rounds приоритета нет.

## Вывод и следующий эксперимент

Короткий план действительно чувствителен к seed; один полный UI-контроль показал, что для mixed-magic202проблема сохраняется и в действующем автоплане. Текущий счётчик меняется постепенно, а случайные перезапуски могут снова уводить в лёгкие низкие counts. Наблюдения обосновывают проверку конкретной гипотезы, а не немедленную смену score или механики.

Следующий эксперимент — **один фактор**: ускорять уже существующий count-directed resize при непустом eligible-наборе одностороннего плато screening=100% (симметрично0%), например проходить часть оставшегося расстояния к bound вместо±1. Unsupported исключать из определения плато; после неоднородных оценок сохранять ADR-0128. Сохраняются состав прежних NPC при resize, admission, random-restart доля, финальный win→rounds score, C/E/V и механика. Уже достигнутый target, min/max, fixed-count/C1 должны сохранить прежний RNG-путь.

Сначала сравнить с сохранёнными шестью112-trial references при тех же source/seed и бюджете. Условие перехода к дорогому контролю: обе застрявшие202строки выходят из100%validation и приближаются к50%, без новых unsupported/proposal cap; показать все другие пары, длительность и wall time, не выбирать лучший seed. Затем сравнить полный202план с текущим reference и отдельный заранее выбранный seed. Улучшенный охват counts сам по себе не является улучшением баланса. Uniform anchors из отклонённого ADR-0127 не возвращаются автоматически. До сравнения production остаётся прежним.
