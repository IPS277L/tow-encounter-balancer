# M7: проверка кеширования NpcRoundResult.continuation

Решение: **не сохранять оптимизацию**. В дополнительном чередующемся сравнении нет убедительного общего выигрыша: на 3×2 медиана хуже примерно на 1,9%, на 2×2 практически равна. Улучшение медианы 2×1 около 9,6% сопровождается перекрытием широких диапазонов. Это не доказательство отсутствия любой пользы, но недостаточное основание усложнять результат по принятому критерию.

Production src восстановлен к исходному содержимому. [Кандидат](m7-round-continuation-rejected.patch) сохранён только как исторический patch, не применяется автоматически. Он добавлял init=False/repr=False/compare=False поле и строил validated continuation один раз после полной проверки steps; source/replay guards не удалялись. Временные семь tests кандидата удалены вместе с отклонённым изменением; итоговый набор tests не расширен.

## Проверки корректности и первые замеры

25 targeted tests кандидата прошли (0,205 с): семь новых и 18 existing round/Blunderbuss tests. Проверялись четыре round outcomes, pending/history, unchanged source, once-only projection, replace/repr/hash/frozen/pickle/deepcopy, source/journal rejection до projection, reload и отсутствие повторного RNG/Attack. До редактирования сохранены три полных 100-trial result/summary; после изменения все три пары полностью равны, включая source. Их canonical digests совпали с исходным mixed baseline.

[Свежий замер до](m7-round-continuation-before-2026-09-29.md) и [замер кандидата](m7-cached-round-continuation-2026-09-29.md): 100 trials, seed=20260929, budget=5, пять wall repeats, отдельные tracemalloc/cProfile. Внутри каждого замера все records/summary равны. Median до/кандидат: 2×1 — 0,266529/0,252417 с; 3×2 — 0,569703/0,572916 с; 2×2 — 0,400679/0,363014 с. Peak Python allocation до/кандидат: 86,6/86,6; 152,7/152,8; 120,9/120,9 KiB (не RSS).

Число построений continuation в профиле сократилось 860→182, 1568→360, 1494→304. Это подтверждает устранение повторной работы, но не гарантирует соответствующего ускорения wall time; cumulative профиль включает вложенные проверки и его строки не складываются.

## Дополнительное чередующееся сравнение

CPython 3.14.5 / Windows 11, тот же компьютер и входы. Два отдельных постоянных Python worker: исходная копия src в build и текущий кандидат. В копии изменён только npc_round_models.py, полученный read-only git show из 4db7a22879671cbb1de4ec4581b20f8641a60557; загруженный путь модуля и source/harness hashes проверены. Другой worker простаивает, пакеты выполняются строго по одному. По пять пар на состав, порядок before/cached чередуется. Перед каждым составом каждый worker выполняет один полный прогрев. Всего 3600 trials; process startup, imports, создание fixtures, gc.collect, digest/JSON/IPC не входят в таймер, summary projection входит. Это проверка локальной оптимизации, **не benchmark process simulation API**.

Для каждого из 36 пакетов совпали digest всех compact records, counts, Attack/visited totals. Само это сравнение не передаёт полные Python results через IPC; их полная equality до/после проверена отдельно выше. ОС/частота CPU/affinity не контролировались, диапазоны перекрываются. Память и cProfile здесь не измеряются.

В отличие от одноразового build-скрипта измерения, архивный probe создаёт новое имя временной папки при каждом запуске. Он не переключает Git и не редактирует production; копии остаются в build. В текущем восстановленном production он намеренно отказывает до создания копии: это исторический эксперимент.

```powershell

.venv/Scripts/python.exe docs/benchmarks/m7_round_continuation_comparison.py
```

Следующий шаг — определить отдельный контракт опционального mixed process runner по существующей bounded spawn-модели M3/M6: exact request/seed/indices, полная equality sequential, отдельные четыре исхода, ограниченная очередь и ошибки без partial result. Автоматический выбор backend и ускорение этим экспериментом не обоснованы; реализация process в этот срез не входит.
