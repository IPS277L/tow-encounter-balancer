# Полный автоматический план динамического генератора

Дата: 2026-11-17. Статус: оба полных поиска завершены. Алгоритм ADR-0128 и модель автоплана ADR-0126 не менялись во время серии.

## Что проверяется

Полный план, который выдаёт текущий UI, исполняется без уменьшения screening/validation. Это наблюдение пользовательской функции на двух сохранённых демонстрационных партиях, не статистическое доказательство качества всех партий/seed. Рендер браузера и HTTP-время не входят в benchmark; выполняется тот же публичный JSON/Python-путь и игровой симулятор.

Партия mixed — два PC из `docs/examples/dynamic/pc-ranged.request.json` (стрелок и melee-боец). Mixed-magic — та же партия плюс первый PC из `elemental-mage.request.json`, переименованный в `mage`. Во всех случаях автоматическое пространство NPC,1–10NPC, цель50%побед/5начатых раундов, предел15, master seed42. Остальные характеристики (Characteristics), навыки (Skills), таланты (Talents), Судьба (Fate), снаряжение (Equipment) и магия сохранены из примеров; готового NPC reserve нет.

Точный план получен исполнением настоящего `PLANNING_SCRIPT` в локальном headless Edge с включённым автоматическим планированием. Python не воспроизводит формулу отдельной копией. Исходники и manifest — `.cache/full-ui-plans/`; helper `.cache/prepare_full_ui_plans.py`. Первоначальный запуск Edge в песочнице был заблокирован Windows ACL профиля; повтор вне песочницы успешно исполнил тот же локальный JavaScript.

| Партия | Кандидаты × screening | Финалисты × validation | Бюджет до trials | ETA UI, с |
| --- | --- | --- | ---: | --- |
| mixed |8×12|2×49|194|299–1493|
| mixed-magic |10×8|2×47|174|298–1487|

Это два полных последовательных поиска. В серии нет повторов с другим master seed или чисто melee-партии; обе партии содержат melee-PC. Новые игровые компоненты/тактика не добавляются, формула плана и seed не подстраиваются после результатов. Бюджет — верхний предел: при отсутствии допустимых финалистов/достигнутом proposal cap фактических trials может быть меньше.

## Воспроизведение и метрики

Developer harness теперь принимает точные экспортированные JSON-запросы через `--requests`; seed/численность/план не заменяются defaults, одновременные overrides запрещены. Вся серия проходит допуск до первого боя. Heartbeat показывает завершённые trials без полного боевого лога. Ошибка исполнения симуляции сохраняет portable replay, число завершённых trials и seed следующего в `.failure.json`; это не универсальный обработчик ошибок summary/encoding.

```powershell
$env:PYTHONPATH = 'src'
.venv/Scripts/python.exe -u tools/benchmark_dynamic.py --requests .cache/full-ui-plans/mixed.request.json .cache/full-ui-plans/mixed-magic.request.json --output .cache/dynamic-full-ui-plan-2026-11-17.json
```

Точный полный source каждого завершённого поиска, все кандидаты, replay, стоимости batches и интервалы сохраняются в artifact. Консольный протокол: `.cache/dynamic-full-ui-plan-2026-11-17.run.log`. Поиск измеряется отдельно от JSON encoding; пользовательское ожидание сопоставляется с их суммой. Диагностические unsupported replays считаются отдельно и не входят в поиск.

Анализ: обе validation-оценки, их интервалы и отклонение от screening, ошибка цели побед/раундов, actual trials, численности, round-limit/unsupported и время против ETA. Победы разных составов не объединяются в общую оценку сложности. Started rounds включают censored prefix.

Старые64-trial поиски ADR-0128 — ориентир, а не независимый парный эксперимент: совпадающие составы/стадийные индексы используют общие префиксы seeds. Screening меняет последующие предложения; magic также меняет ширину8→10. Интервалы относятся к фиксированному составу; выбор лучшего из двух validation-финалистов не даёт одновременной гарантии ранжирования или глобального оптимума.

## Вывод и следующий шаг

Всего368/368запланированных trials, две поддержанные рекомендации,0unsupported и1screening round-limit. По точечным оценкам обе рекомендации близки к50%, длительность выше цели5. Первая партия уложилась в10–15мин, вторая немного вышла за15мин; оба расчёта вошли в показанный широкий ETA. Два прогона на одном master seed не доказывают устойчивость между seed или для остальных партий.

47/49validation trials дают около±14п.п. вблизи50%, а не±5п.п. Увеличение общего бюджета поиска не превращает все его бои в выборку одного состава. Текущий автоплан пригоден для предварительного подбора в проверенных случаях; уверенность в точном проценте и истинном порядке финалистов ограничена.

**Следующий обоснованный приоритет — распараллелить trials фиксированного кандидата**, сохраняя последовательную адаптацию поиска, детерминированные seeds, progress и отзывчивую отмену. ОС сообщает16логических CPU; оба измерения выполнялись последовательно. Коэффициент ускорения пока не измерен. Существующий `pc_melee_parallel` полезен как основа, но его batch32даёт лишь1–2задачи для нынешних screening/validation, pool создаётся заново и API не поддерживает progress/cooperative cancellation. Простое изменение числа workers недостаточно.

Перед реализацией нужно согласовать публичную execution-границу dynamic JSON/Python, малые batches/жизненный цикл pool и остановку уже выполняющихся workers. После фактического ускорения — увеличивать полезную точность в прежнем временном ориентире. Увеличение sequential budget, очередная правка UI/JSON или сокращение validation не являются первым действием по этим данным.

## Проверка инструмента и воспроизводимость

Developer harness дополнен точными экспортами, heartbeat и portable failure diagnostic. Семь адресных tests.unit.test_dynamic_benchmark прошли2.845s после снятия ограничения Windows tempfile ACL; после исправления строгого raw JSON admission —7OK/3.607s. Три ошибки первоначального запуска были WinError5в собственных tempfile-каталогах. Повторяющиеся ключи теперь отвергаются до `json.loads`, override/невалидная вторая заявка — до первого боя; observer сохраняет полный результат/seed, failure diagnostic — точный следующий trial.

Канонические Edge-входы не содержали повторяющихся ключей. Исправление загрузчика не изменило уже запущенный процесс/измеренные данные; фактически использованный harness сохранён в `.cache/full-ui-plans/benchmark_dynamic.measured.py`. Его SHA-256 `a92881c01b6348c2ac199e6619ae8a3e9a700853f6bb1a2788d8c32a1683c16c` совпадает с artifact. Production source digest `ef70619801288ee101688594dd5d6da6eecaae7939fba87836f0fda95448580f` совпал до/после серии; игровой код и UI planner не менялись.
