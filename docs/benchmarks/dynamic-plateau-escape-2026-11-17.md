# Ускоренный выход из крайнего плато численности

Дата: 2026-11-17. Статус: сравнение завершено, гипотеза отклонена; прежний рабочий алгоритм восстановлен.

## До сравнения

[ADR-0131](../decisions/ADR-0131-adaptive-count-step-on-extreme-plateaus.md) фиксирует формулу, независимые показатели и gates до запуска candidate. Меняется только размер уже выбранного count-directed шага: ceil(remaining_distance/2) при непустом eligible-наборе всех win rates1/0; иначе прежний1. Parent, branches/restarts, score, budgets, kernel, JSON и RNG-схема не меняются. Исходные NPC сохраняются, при shrink sequential pop сохраняет порядок оставшихся. Нет нового правила монотонной трудности и обязательных uniform anchors.

Шесть exact inputs/reference results — [прошлый контроль](dynamic-stability-2026-11-17.md). План каждого112trials (6×8 +2×32), seed42/202, process4. Reference mixed303/112снят отдельно до правки; его вход/результат `.cache/adr131/mixed-303.request.json` и `reference-303.json`. Формула/gates после этих данных не подбирались. Candidate inputs в точности те же; все строки/длительность/время показываются независимо от успешности гипотезы. Равное число trials не гарантирует равное время более трудных боёв.

До изменения сохранён полный application snapshot `.cache/adr131/dynamic_encounter.reference.py` со всеми прежними незакоммиченными правками. Сравнение собственного diff подтвердило только новый helper и цикл добавления/удаления. Откат при провале затрагивает только эксперимент, не весь пользовательский working tree.

## Повтор фиксированных составов: заранее заданный контроль404

План до запуска: master seed404,64trials на каждый из двух полных native sources, process4/batch1. Изменяются только simulation и execution; request/scenario/party/NPC facts сохраняются. Input admission проверяется заранее, исходники и source hash фиксируются. По одному pool на состав; других тяжёлых прогонов одновременно нет. Старые32trials не объединяются с новой выборкой, поскольку они участвовали в выборе финалистов.

Сохраняются полные текущие JSON results и compact per-trial index/seed/outcome/rounds для сопоставления. Одинаковые индексы имеют одинаковые trial seeds; это парный контроль разных боёв, не128независимых сравнений. Показатели — outcomes с исходным знаменателем64, win/round intervals, число defeats/round-limit/unsupported и фактическая стоимость. Если есть unsupported, они не становятся поражениями: показываются confirmed-win fraction и границы с учётом неизвестных исходов, paired summary отдельно отмечает такие пары.

Новый seed проверяет воспроизводимость разрыва между целыми композициями. Даже повторный разрыв не изолирует Toughness/оружие/таланты; причинный вывод об одном компоненте требует отдельного контроля. Формула поиска/правила не меняются, результаты не подгоняются под целевые50%/5раундов.

### Воспроизводимость и решение

Локальные artifacts в `.cache/adr131/fixed-404/`: два полных `*.request.json`, текущие `*.result.json`,64упорядоченных records в каждом `*.trials.json`, `measurements.json` и `comparison.json`. Они являются локальным измерением, а не публичным save/resume-контрактом; `.cache` нужно переносить отдельно, если нужен точный повтор на другом компьютере. Постоянный итог/ограничения сохраняет этот документ.

```powershell
$env:PYTHONPATH = 'src;.'
.venv/Scripts/python.exe -u .cache/adr131/run_fixed404.py
.venv/Scripts/python.exe .cache/adr131/validate_fixed404.py
```

Первый script выполнен один раз с реальным spawn4 вне sandbox из-за известного ограничения Windows pipes. Второй не запускает боёв: проверяет обе текущие result schemas, полный source echo, неизменность всех исходных полей кроме simulation/execution,64уникальных индекса/ожидаемых seed, попарное совпадение seed и согласованность outcomes/actions/rounds с агрегатами. Все проверки пройдены; исходный код до/после совпал. Полный regression/wheel ради неизменённой механики не запускались; последняя проверка восстановленного поиска остаётся46OK/31.702s.

Разрыв между целыми композициями повторился на свежей выборке: причина прежнего ухудшения не сводится к шуму тех32validation trials. При этом влияние отдельной характеристики/предмета/таланта не выделено. Новые данные не реабилитируют отклонённый count-step и не требуют менять счёт/правила.

После этого контроля проверена гипотеза масштаба компонентной мутации при сохранении численности: два разных NPC вместо одного только в прежней component-ветке. [ADR-0132](../decisions/ADR-0132-two-member-component-mutation.md) сохраняет заранее заданный план, все шесть пар и отрицательное решение; исходный runtime восстановлен,505не запускался. Это не причинный эксперимент одной Toughness и не основание для настройки под42. Актуальная очередь находится в [статусе](../project-status.md#следующий-шаг).
